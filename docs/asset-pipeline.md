# Asset pipeline

All mod art is generated by one scripted pipeline under `tools/art/`. Nothing is hand-painted in an editor, so every texture, element model and guide illustration can be rebuilt byte-for-byte. The files are original work under the mod's All Rights Reserved license; see [assets.md](assets.md). There is no GeckoLib dependency and no `AnimationDefinition` clip. Mob motion is `EntityModel.setupAnim` posing the parts already synced through `MobActions`.

## Rules

- **One density: 32x.** 2 texels per model unit everywhere: item sprites 32×32, block faces 32 texels per 16 units, entity skins 128×128 on 64-unit layouts, particles 32×32, guide pages 512×256 in a 256×128 art box. The single exception is the underside of the archive vault (half density, never seen in play). Mod art sits at twice the vanilla texel density on purpose (the visual brief asked for detailed 32x art); the palette and outline keep it from looking like a foreign pack next to 16x vanilla blocks.
- **One light.** Top-left key light on every sprite and face; shadows lean cool (indigo/violet), highlights lean warm. One outline colour, deep ink `#141224`, applied as a selective outline (lighter where the sprite is lit).
- **Materials, not flat colour.** Every surface comes from the material library (below) with its own grain and its own wear: brushed and scratched metal, patinated copper, chipped stone, fibre paper with stains, woven cloth with frayed edges, glowing gel, faceted crystal, glass with a rim glint.
- **Silhouette first.** Each item reads as a shape at 16 px on screen (GUI scale 1) before any detail; blocks keep a strong outline from the GUI angle and from eye height.
- **No gameplay in art.** Models change only visuals. Collision and occlusion shapes stay in Java.

## Running

```
python tools/art/build.py                 # regenerate everything into src/main/resources/assets/mnemolith
python tools/art/build.py --check         # rebuild into a temp dir; exit 1 if any file differs (CI-friendly)
python tools/art/build.py --only items,blocks
python tools/art/validate_assets.py [--vanilla <extracted client assets>]
python tools/art/preview.py --before <git rev> --out <dir> [--vanilla <extracted client assets>]
```

Python 3.10+, Pillow and numpy. Every asset seeds its random source from its own name (`mnart.core.rng_for`), so output does not depend on build order. `build.py` also deletes files the pipeline replaced (`STALE`), so a rename never leaves an orphan texture behind.

## Layout

| Module | Role |
| --- | --- |
| `mnart/palette.py` | 25 seven-step ramps (index 3 is the base tone), outline and shadow colours, temper accents |
| `mnart/core.py` | Canvas, masks, depth/edge maps, value noise and fBm, shading modes (flat, cylinder, sphere, gradient), selective outline, wear marks (scratches, chips, grime, speckle, glint, crack, stitch) |
| `mnart/materials.py` | Material library: `surface(mat, w, h, rng, face, bevel, wear, tile)`; rivets, insets, raised panels |
| `mnart/shapes.py` | Rods with a lit edge, rings, gems, paper slips, the small figure, glow |
| `mnart/modelgen.py` | Element-model builder: boxes with per-face material or painter, packed into one 64×64 sheet per model (UV = texel / 4), identical faces share a region, auto cullface on faces flush with the block edge, vanilla `block/block` display transforms |
| `mnart/items.py` | The 20 item sprites |
| `mnart/handheld.py` | The in-hand element models for the chronicle lens and the extraction needle |
| `mnart/blocks.py` | The block element models and `scar_glass` |
| `mnart/entities.py` | Entity skins (128×128) and the preview-only wanderer skin |
| `mnart/entity_models.py` | Part trees transcribed from the Java `LayerDefinition`s, for offline renders only; keep in sync by hand |
| `mnart/particles.py`, `mnart/gui.py` | Particle sprites; panel, slot and tag icons |
| `mnart/guide.py` | The 26 field-guide pages |
| `mnart/render3d.py` | Small software renderer for JSON models and entity boxes (guide dioramas and previews) |
| `build.py`, `validate_assets.py`, `preview.py` | Entry points |

The old per-feature scripts (`graft_art.py`, `residue_art.py`, `storm_art.py`, `relay_art.py`) are gone; everything they drew is now part of this pipeline.

### In-hand models

`items/chronicle_lens.json` and `items/extraction_needle.json` select on `minecraft:display_context`, exactly like the vanilla spyglass: GUI, ground, item frame and shelf keep the flat sprite; hands get `models/item/<name>_in_hand.json`, a multi-element model (lens: octagonal copper ring, translucent amethyst glass, grip; needle: tip, ferrule, shaft, grip, pommel). Both lie on the sprite's diagonal so the vanilla handheld transforms apply. Their sheets are `textures/item/<name>_model.png` (64×64, UV = texel / 4).

## Blocks

Parent `minecraft:block/block` with the vanilla display transforms. One 64×64 sheet per model at `textures/block/<model>.png`; UV = texel / 4, so a 16-unit face uses a 32-texel region. Faces flush with the block edge carry a cullface. Element rotations are 22.5° or 45°. The `particle` texture is a separate 32×32 tiling sprite of the block's dominant material (`textures/block/<model>_particle.png`; the two vault variants share one), because break particles sample random corners of that sprite and a packed sheet has empty gaps.

| --- | --- | --- |
| `archival_stratum` | 2 | Navy core column with bone and verdigris strata; a protruding band at y 5–9 |
| `mute_stone` | 8 | Chipped plinth, banded body, lip and cap with a hush seal on top; four iron clamps |

## Entities

Layer definitions stay at 64×64 texture units; the PNGs are 128×128, so every UV below is in 64-unit space and each unit holds 2×2 texels (the same 32x density as items and blocks). No Java change was needed: `LayerDefinition.create(mesh, 64, 64)` normalises UVs, so a 128×128 file maps onto the same regions. Model y grows downward. Feet sit at y 24. North (−Z) is the face the mob looks along. Cube UVs follow `ModelPart.Cube` with origin `(u, v)`, size `(w, h, d)`, and no mirror:

| Face | U | V |
| --- | --- | --- |
| Down | `u+d` … `u+d+w` | `v` … `v+d` |
| Up | `u+d+w` … `u+d+2w` | `v` … `v+d` |
| West | `u` … `u+d` | `v+d` … `v+d+h` |
| North | `u+d` … `u+d+w` | `v+d` … `v+d+h` |
| East | `u+d+w` … `u+d+w+d` | `v+d` … `v+d+h` |
| South | `u+d+w+d` … `u+d+2w+d` | `v+d` … `v+d+h` |

None of the three has eyes. They are not recolored zombies.

### Echo strider

Pivot of the body is `(0, 15, 0)`. Head and fins are children, so a charge rotates them with the body. Legs stay on the root.

| Part | texOffs | Box | Pivot |
| --- | --- | --- | --- |
| body | 0, 0 | (−10, −2, −3) 20×4×6 | (0, 15, 0) |
| head | 0, 12 | (−3, −3, −3) 6×5×3 | local (0, −1, −3), blank bone plate |
| fin_left | 0, 22 | (0, −2, −4) 1×3×8 | local (10, 0, −1) |
| fin_right | 20, 22 | (−1, −2, −4) 1×3×8 | local (−10, 0, −1) |
| leg0–3 | 0, 34 | (−1, 0, −1) 2×8×2 | (±6, 16, ±3) |

Walk swings opposite leg pairs. `TELEGRAPH` (the charge) leans the body to `xRot` 0.7 and opens the fins. `ATTACK` pushes the plate forward. `PHASE` scales the body to 0.7. A slow bob is the glide. Shimmer is the fin color and that bob. The renderer stays on the cutout path `MobRenderer` already uses.

## Particles

Sprites in `textures/particle/` are 32×32 white shapes with a soft alpha halo: star (`imprint_shimmer`), mote (`graft_mote`), dash (`imprint_extract`), plus (`compose_success`), X (`compose_fail`), ring (`pressure_warn`), blob (`mute_haze`), chevron (`strider_trail`), hook (`archivist_snatch`), diamond (`replicant_telegraph`). They stay white because `MemoryParticle.setColor` multiplies the sprite; the colours are the values in `ClientParticles`, and the five graft particle types take the temper colours.

## GUI

`textures/gui/panel.png` is 64×64 with an 8-texel frame; the screens nine-slice it with a 4-unit border normalised to a 32-unit panel, so the file size is free. `slot.png` is 36×36 for the 18-unit slot. `tags.png` is 288×32: nine 32×32 tag icons in `ImprintTag` order (fire, fall, death, build, explosion, silence, player, redstone, path). `textures/misc/pressure_vignette.png` is unchanged (a soft full-screen gradient with no texel detail).

## Field guide

26 pages, `textures/gui/guide/<page>.png`, 512×256. `GuideScreen` blits them into a 256×128 art box with the image size passed in, so the double density needs no code change. Every page shares one plate: ink-dyed paper with fibre and a faint diagonal ruling, a navy and verdigris frame with brass corner studs. Each page has one isometric in-world diorama rendered by `render3d` from the real block models and entity layouts (turf and stone ground drawn by the pipeline, never vanilla textures), the item sprites at 2× or more, and simple diagram marks (arrows, gauges, tag icons, dotted pips). Pages carry no text; the words come from the lang file. The echo in the pictures is the pink silhouette layer (`EchoRenderer.SILHOUETTE_TINT`), grafted echoes use the temper colours.

## Validation

`validate_assets.py` follows every reference the client would: blockstate variants and multipart to models, item definitions (including `select` cases) to models, model parents and `#texture` variables to PNGs, particle definitions to sprites, `textures/...png` paths hard-coded in Java, and `GuideBook.PAGES` to 512×256 pages. It checks registry coverage (every `ModItems` id has an item definition, every `ModBlocks` id a blockstate), element coordinates in −16..32, UVs in 0..16, cullface names, rotation angles, the resolution rules above, and warns about textures nothing references. With `--vanilla` it resolves `minecraft:` references against an extracted client jar; without it, against a short list of known vanilla files.

## Previews

`preview.py` writes before/after sheets (items, blocks from the GUI angle, entities, raw textures, guide pages), an inventory grid at 2× GUI scale, block models from two corners, first-person and third-person hands (with a vanilla sword through the same code path for scale), and an in-world perspective scene with vanilla context blocks when `--vanilla` is given. The renderer uses vanilla face shading and display transforms, but no lightmap, ambient occlusion, fog or emissive layers, so treat the previews as a check on shape, material and scale; final lighting still needs an in-game look (see `qa-checklist.md`).

## Out of this pass

A rebuilt observatory, a decoration set, and a music loop. The relay and the vault reuse vanilla sounds too (lead tied, untied and break; amethyst chime, resonate and cluster break). The Scar and the recollection storm reuse vanilla sounds (amethyst resonance and break, warden emerge and sonic charge) plus `pressure_warn` and `lens_focus`; there are no new sound files. The reel does not have a block-entity idle animation.

Known visual limitation, not changed here: `mute_stone`, `composition_reel`, `resonator_trap` and `archival_stratum` have models smaller than a full block while their blocks keep full occlusion, so a neighbouring block's hidden face can show as a gap at the base. Fixing it means `noOcclusion()` in Java, which changes lighting and culling behaviour, so it is left for a gameplay-reviewed change.
